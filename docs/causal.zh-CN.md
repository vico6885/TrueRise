# 因果完整性引擎

[English](causal.md) | [简体中文](causal.zh-CN.md)

Agent 声明越来越多地说因果语言："这个工具让 agent 变强了"、"这个技能导致了回退"、
"这个改进跨环境成立"。相关级证据承载不了这些句子——但大多数评测 harness 没有办法
把这一点说出来。TrueRise 交付一个**领域中立的因果完整性基底**
（`crates/truerise-eval/src/causal/`）：给证据所能承载的声明类型分级、给缺失的
手续定价、拒绝跳过手续的设计。

诚实边界，一次说清、处处执法：这些原语**给证据定价、拒绝设计；它们不证明因果**。
识别假设始终是判断——基底强制它们被声明、捍卫它们的算术、把跳过手续的声明降级。

## 六值声明分型（CA1）

每条带因果色彩的声明被分型到六个值之一，从弱到强：相关 → 观察性因果 →
干预性因果各层，每层有自己的措辞法。相关级声明不说因果语言；宣称门
（`tools/check_claim_terms.py`）执法措辞，分型执法层级。

## 假设账本（CA2）

`assumption_ledger.json`（仓库根）把识别假设声明为机器可查的行——每条假设一行，
带来源类别与声明层级。**没有完整行，就没有因果层级**：缺手续的因果声明被降级为
`INCONCLUSIVE`，而不是通过。解析器在 `crates/truerise-eval/src/causal/ledger.rs`；
账本文件本身就是活例子。

## 识别算术（CA3）

- **Manski 无假设区间**（`bounds`）：不做任何识别假设时平均处理效应的区间——
  任何因果声明必须越过的诚实地板。
- **E-value**（`evalue`）：混杂脆弱性价格——要多强的未测混杂因素才能解释观测效应。
- **不变性筛查**（`icp`）：哪些关系跨环境存活（题包间稳定性问题）。
- **反驳器电池**（`refute`）：安慰剂结果、子集稳定性、混杂注入——每个反驳器都是一个具名测试。

## 实验原语（CA4）

种子化、字节可复现的随机化流（`rng`）、区组 / 整群 / 交叉分配设计（`design`——
SUTVA 修复）、小样本研究的随机化推断（`permutation`）、干预性功劳分配（`shapley`）。

## 形式化失败归因（CA5）

Halpern–Pearl 实际因果 + 责任分数，作用于二值有界模型（`attribution`）：
当一次运行失败时，基底回答"哪个组件**实际上**导致了失败"——给形式化、可重算的
判词，而不是一段散文猜测。

## 准实验扩展

受控实验不可行时，基底携带标准观测设计：双重差分、断点回归、Wald IV、倾向匹配、
合成控制、效应修饰、成对评分聚合、最小对构造（`quasi`、`pairwise`、`minimal_pair`、
`adjust`、`synthetic`）。

## 如何消费

- 每个族都有具名测试：`cargo test -p truerise-eval causal` 跑基底套件
  （同样见于 `spec_map.json` 的 因果宣称 / 因果识别 / 因果归因 行）。
- 把假设写进 `assumption_ledger.json`——解析器拒绝不完整的行。
- 因果层级措辞与其他所有承诺一样走宣称门：A/B/C 承诺分级见
  [`limits.md`](limits.md)，CA1–CA5 落地条目见
  [`CHANGELOG.md`](../CHANGELOG.md)。

## 与系统其余部分的关系

- 分型结果接入 **INCONCLUSIVE** 降级（三值判词，README"两个极端都诚实"）。
- 假设账本被**写闸**（G29）消费：写入持久状态的未验证假设会——可见地——
  存活到后续证书里。
- 反驳器电池是沙箱必失探针在评测侧的对应物：一个给证据定价，一个给执行定价。
