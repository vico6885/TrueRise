# RFCs

EN: Port-trait changes (ModelRouter / SandboxProvider / MemoryBackend) and
wire-schema breaking changes require an RFC here:
motivation, alternatives, wire compatibility, migration. Two maintainer
approvals. No RFC, no change.
Adding a fourth port trait (`ToolProvider`, named by the construction spec but
not implemented — see `../../providers/README.md`) is itself an RFC-gated act.

CR: 端口 trait 变更与 wire 破坏性变更须先立 RFC（动机/备选/wire 兼容/迁移），
两名维护者批准。无 RFC 不变更。补出规格点名但未实现的第四端口 `ToolProvider`
同样要走 RFC（见 `../../providers/README.md`）。
