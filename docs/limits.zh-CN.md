# 边界（Limits）

[English](limits.md) | [简体中文](limits.zh-CN.md)

本框架能强制什么、只能测量什么、永远不承诺什么。本页是硬边界声明，不是免责声明。

## 自指边界

校验层无法校验自己的目标。判据是否度量了真正想推进的东西（构造效度）、目标本身是否选对（Goodhart），都不在机制可判定的闭包里。因此：

- **机制层**：未支撑的断言、未申报的桩、缺项的台账、不可比的对比、未批准的合并、无依据的放弃——全部变成机器可拒。
- **程序层**："目标是否选对"变成必须封盘、必须署名、必须版本化、必须被外部评审的公开对象，而不是假装它能被算法验证。

凡越过这条边界的句子（"不会跑偏""无幻觉""绝不误导"）恰恰是本项目自己的宣称门要拒的那类声明。宣称门（`tools/check_claim_terms.py`）对下列受保护面执法承诺分级措辞。

## 承诺分级

本项目每一条治理承诺都分级。分级登记在 `claim_terms.json`（`promise_grades`）并做闭合机检：每个 backlog 包至少出现一行，行按（包，切面）唯一，未知级别直接拒绝。

| 级 | 含义 | 例 |
|---|---|---|
| **A 可强制** | 机制会拒绝生成产物 | 未支撑断言、未申报桩、预算不等臂对比 |
| **B 可测量** | 机制公布自己的精度与代价 | 拦截精确率/召回率、闸门净收益账 |
| **C 只能降低** | 机制降低概率，永不到零 | 精心构造的欺骗、误导措辞、目标选择 |

执法规则：宣称门拒绝任何把 C 级结果升级成 A 级措辞的句子（guarantee 族词）。白名单行必须自带显式否定——门会机检这一点，边界句必须写"不承诺"，不能写"承诺"。

## 永不承诺的事项

1. 开放世界真伪。本框架拒收**无支撑**的陈述、重算**封闭形式**的陈述；它不认证、也无法认证开放世界陈述为真。
2. 目标正确性。封盘目标只是"已声明、已署名、已版本化"，不是"已验证"。
3. 用户满意。满意是结果不是判据；本框架强制的是逐项证据、缺口披露与自助验证。
4. 自身完整性。闸门咬合自身也要被测（变异演练）；未被测试咬合的闸视为不存在，而不是默认可信。
5. 无竞态的意图核验。mid-run 意图检查在 run 结束后重读合同文件：慢速 provider 调用期间"改了又改回"的窗口（TOCTOU）仍然存在。链上的封盘行限制了损害（run 后的任何分歧仍会浮现）；彻底关窗需要合同文件的 OS 级锁，写闸批次已落地，OS 级文件锁仍未完成。
